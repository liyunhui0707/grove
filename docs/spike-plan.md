# 首个 Spike：历史范围参考

本文为最初计划，不能作为当前完成清单或下一阶段指令。当前已有公开技术预发布，实际支持与待办见 [current-status.md](current-status.md)；最初私有评估和逐阶段笔记已归档在忽略区。

2026-11-08：本机核心闭环已实现并验证，见 current-status.md 和 verification.md。万张性能、真实手机格式、色彩和 Windows/Linux 仍待验收，不能将全部阶段 1 标准记为完成。

## 目标

在独立项目中完成可运行的桌面工作流：打开测试目录 → 网格 → 单图审片 → 评分/撤销 → 多图比较 → 重启恢复。
用户已授权开始，不需要再次询问是否开发。先做这个闭环，不试图交付整个成熟产品。

## 建议实现顺序

1. 检查已有工具版本；按官方文档选择相容的 Tauri 2/React/TypeScript/Vite 依赖，不覆盖全局配置。
2. 先实现统一设计令牌与浏览、单图、比较三种视图；浅暗主题、键盘焦点、错误/空/加载状态一起设计。
3. Rust 端限制到用户选择的测试目录，建立扫描和分页数据接口，前端虚拟网格。
4. SQLite 实现 nullable rating、更新与重启恢复；有针对性地测试七态、批量与撤销。
5. 连接缩略图/预览缓存和异步调度；先 JPEG/PNG/WebP，少量 HEIC 走独立验证。
6. 单图评分自动下一张，稳定审阅队列和撤销恢复；测试快速切图时评分目标。
7. 2–8 张比较、活动窗格、同步视口、临时细节查看；限制原始大图并发与常驻。
8. 在明确的测试副本上验证 XMP 写出/读取、0 与未评分的映射、保留未知字段。
9. 跑适当的单元/集成检查，构建本机桌面应用并人工查看；记录证据、限制和下一步。
10. 尽早验证 Windows/Linux 构建路径；没有实际运行证据时标明待验收。

## 接受标准

- 未评分、0、1–5 全部可分别显示、过滤、保存、撤销；重启不混淆。
- 单图数字评分后下一张；文本输入时不误评分。
- 快速加载/切换时不会给错误文件评分；过滤移除当前项后位置稳定。
- 2–8 张和奇数布局可用；比较键盘只操作活动窗格。
- 默认八图加载屏幕预览，细节加载按需，任务有并发/内存上限。
- 扫描渐进显示，损坏与不支持状态明确；过期任务结果不替换当前图。
- 原始测试图片操作前后哈希相同；XMP 仅写指定测试副本。
- 浅/暗主题和三个主界面有实际截图或人工验收记录。
- 构建、测试、格式支持和性能分开记录：不能把目标写成测量结果。

## 测试素材

使用生成图或有许可的素材；交互测试目录放在仓库外。覆盖方向、横竖图、不同尺寸、透明度、中文/空格路径、同名文件、损坏文件及少量合法 HEIC。
不自行搜索、读取或使用家庭主库。二进制素材不得为方便而整批加入 Git。

## 暂不实现

移动、删除、隔离、覆盖、完整批量整理、专业调色/RAW 显影、视频播放器/剪辑、AI、人脸、云同步、复杂地名服务、正式官网/发行。

## 性能目标与记录

先固定测试电脑、素材数量与像素、存储介质、缓存冷暖和发布/开发构建。
可讨论暖缓存 JPEG 切换 P95 约 150ms、无持续滚动卡顿、30 分钟无无界增长；这些尚未测量，也不是对所有格式的保证。
HEIC 冷解码单独统计，测量包括 Rust、WebView、GPU 和解码临时内存，不只看 JS 堆。
